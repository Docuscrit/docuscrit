# DocuScrit Official Site

Production-ready Vite + React marketing site for the DocuScrit compliance workflow platform.

DocuScrit is positioned as the umbrella brand for:

- Vendor COI Automation
- Legal Escalation & Claim Packet Workflow
- Compliance Risk Visibility

## Commands

```bash
npm ci
npm run dev
npm run typecheck
npm run lint
npm run build
npm run validate:launch
npm run verify
```

`npm run verify` runs the release checks:

```bash
npm run typecheck && npm run lint && npm run build && npm run validate:launch
```

## Phase 3 production architecture

The build now creates crawlable, route-specific HTML rather than empty SPA shells.

1. `vite build` creates the browser bundle.
2. `vite build --ssr` creates a temporary server-rendering bundle.
3. `scripts/postbuild-routes.js` renders each route into its HTML entry file.
4. The temporary server bundle is removed.

Generated routes include:

- `/`
- `/vendor-coi`
- `/legal-escalation`
- `/compliance-risk-visibility`
- `/security`
- `/resources`
- `/demo`
- `/privacy`
- `/terms`
- `/404.html`

The client uses `hydrateRoot` so the prerendered content becomes interactive without replacing the initial page markup.

## SEO and discoverability

Route metadata is defined in:

```txt
src/content/site-data.json
```

Shared runtime and build-time JSON-LD is defined in:

```txt
src/utils/structuredData.ts
```

The sitemap is generated from the same route data:

```bash
npm run generate:sitemap
```

Static route HTML and social metadata are generated by:

```txt
scripts/postbuild-routes.js
```

## Analytics and attribution

GA4 event tracking includes:

- `page_view`
- `product_view`
- `product_cta_click`
- `demo_form_start`
- `demo_form_submit`
- `demo_form_error`
- `resource_open`
- `navigation_click`
- `email_fallback_click`

The demo request payload preserves first-visit landing page, referrer, UTM values, and `gclid` when available.

Analytics can be disabled with:

```txt
VITE_DISABLE_ANALYTICS=true
```

## Accessibility and browser QA

The demo form includes field-level errors, an accessible error summary, `aria-invalid`, and `aria-describedby` relationships.

Run the browser QA script against a preview server:

```bash
npm run preview
SITE_URL=http://127.0.0.1:4173 npm run qa
```

The QA script checks all routes at desktop and mobile sizes for:

- one page-level heading
- main and skip-link landmarks
- horizontal overflow
- unlabeled form fields
- missing image alternative text
- reveal-animation failures
- browser console errors
- basic load and transfer metrics

The JSON report is written to:

```txt
review/qa/qa-report.json
```

## CSS organization

Phase 3 consolidated the older layered CSS modules into five top-level stylesheets:

```txt
src/styles/tokens.css
src/styles/global.css
src/styles/layout.css
src/styles/components.css
src/styles/utilities.css
```

`components.css` retains documented section boundaries and the previous cascade order while removing overlapping legacy module imports.

## Hosting

Cloudflare Pages settings:

- Build command: `npm run build`
- Build output directory: `dist`
- Root directory: repo root, unless this folder is nested

Unknown routes are served through `404.html` with a 404 response using `public/_redirects`.

## Environment variables

Copy `.env.example` or set these values in the hosting provider:

- `VITE_FORM_ENDPOINT` — public Formspree endpoint for demo requests.
- `VITE_GA4_MEASUREMENT_ID` — optional GA4 measurement ID.
- `VITE_DISABLE_ANALYTICS` — set to `true` to prevent GA4 loading.
